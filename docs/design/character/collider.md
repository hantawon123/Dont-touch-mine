# 캐릭터 콜라이더 — 비주얼 기준 치수

플레이어 충돌체를 실제 메시 실루엣에서 뽑아낸 근거를 남긴다.

## 측정 방법

`Assets/_Game/Content/Characters/SmoothBear/SmoothBear.fbx` 를 Blender로 불러
바인드 포즈 정점을 0.1 m 높이 구간으로 잘라 반폭을 쟀다. 프리팹의 `Visual`
자식은 **localScale 0.85**, localPosition 0 이므로 모든 수치에 0.85를 곱해
게임 안 크기로 환산했다. 발바닥이 트랜스폼 원점이고 캡슐 바닥도 원점이라
두 값은 바로 비교된다.

FBX 임포트는 `globalScale: 1`, `useFileScale: 1` 이라 FBX 단위가 그대로 미터다.

## 측정값 (게임 크기, 반폭 = 중심에서 표면까지)

| 높이 구간 | 부위 | 반폭 |
|---|---|---|
| 0.0 ~ 0.3 | 신발 · 다리 | 0.262 ~ 0.273 |
| 0.4 ~ 0.7 | 배 · 골반 | 0.287 ~ **0.304** |
| 0.8 ~ 1.0 | 가슴 · 어깨 (팔 제외) | 0.275 ~ 0.289 |
| 1.1 ~ 1.4 | 머리 | 0.296 ~ **0.307** |
| 1.5 ~ 1.6 | 정수리 | 0.197 ~ 0.268 |

- 전체 키: 몸 1.670 m, 복면(Hood) 껍질까지 1.685 m
- 복면 껍질 반폭: 0.356 (니트 천 레이어라 몸통보다 0.05 더 나옴)
- 팔을 옆으로 내린 상태의 반폭: 약 0.425 (이동 충돌체에는 쓰지 않는다)

## 선택한 값

| 항목 | 이전 | 현재 | 근거 |
|---|---|---|---|
| Radius | 0.27 | **0.31** | 몸통 0.304 · 머리 0.307 을 덮는 최소값 |
| Height (서기) | 1.67 | 1.67 | 몸 최고점 1.670 과 이미 일치 |

이전 0.27은 실루엣에서 **가장 좁은 부위(신발·다리 0.27)** 를 따온 값이라,
정작 조준하게 되는 몸통·머리가 충돌체 밖으로 12 % 삐져나와 있었다.

복면 껍질(0.356)까지 덮지 않은 이유: 이동 캡슐이 지금보다 32 % 뚱뚱해져
문틈·진열대 사이 통행 폭에 영향을 준다. 복면은 몸에 붙은 천 레이어라
맞기 판정 기준으로는 몸통 폭이 더 맞다.

웅크리기 1.1 · 엎드리기 0.56 (`MovementConfig.asset`) 은 이번에 재지 않았다.
해당 포즈 메시를 따로 재야 한다.

## 레이어

- KCC 캡슐(`KCCCollider`, 런타임 생성)은 **layer 6 Player**
- 오프라인 `PlayerCharacter` 루트도 layer 6 으로 맞춰 온·오프라인이 같은
  레이어를 쓰게 했다. 펀치 판정이 Player 레이어만 훑기 때문에 이게 어긋나면
  오프라인에서 주먹이 통과한다.
- 물리 충돌 매트릭스(`DynamicsManager.asset`)는 전부 켜져 있다. 캐릭터끼리
  통과하던 원인은 매트릭스가 아니라 KCC 자체의 `CollisionLayerMask` 였다.

## 재현

```bash
blender -b --factory-startup --python <측정 스크립트> -- <SmoothBear.fbx 경로>
```

정점을 0.1 m 구간으로 묶고, 팔 계열 본(`Shoulder*`/`UpperArm*`/`Arm*`/`Hand*`/
`Finger*`)이 주 가중치인 정점은 빼야 T포즈 팔이 몸통 폭을 오염시키지 않는다.
