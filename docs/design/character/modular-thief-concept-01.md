# 분리형 도둑 캐릭터 스케치 01

2026-09-11 요청 기준의 제안. 모델링·액션 검증 완료본이 아니다. 기존 main-character.md의 색상만 변경하는 MVP 범위보다 이번 요청의 5개 부품 커스터마이징을 우선한다.

## 형태

수달 참고 이미지의 부드러운 배형 몸통, 큰 볼, 짧은 다리를 반영한다. 라벤더 니트 복면, 차콜 몸, 큰 흰 눈, 작은 미소, 분홍 발을 기본 조합으로 한다. 팔은 운반 동작이 가능하도록 길이를 유지하고, 다리는 무릎과 발목이 작동할 공간을 남긴다. 복면 귀는 복면 부품에 포함한다.

## 부품 계약 제안

| 부품 | Blender 구성 | 변경 범위 |
|---|---|---|
| 몸통 | Body: 기본 머리·몸통·팔·손·다리, 기존 리그로 스키닝 | 색·재질, 제한된 체형 변형 또는 검증된 메시 교체 |
| 복면 | Hood: 귀를 포함한 독립 쉘 | 귀 모양·색·니트 무늬, 목 주변 관통 확인 |
| 발 | Feet_L / Feet_R: 발목에 겹쳐지는 독립 메시 | 발/신발 형태·색, Foot.L/R 및 필요시 발가락 웨이트 |
| 눈 | Eyes: 좌우 흰자·동공의 별도 그룹 | 모양·동공 색·시선·눈깜빡임 |
| 입 | Mouth: 얼굴 표면 위 얇은 독립 메시 | 미소·놀람 등 형태와 색 |

눈과 입은 Head를 따라가고, 얼굴 표면과 충분한 간격을 유지한다. 교체용 몸통도 같은 리그·바인드 포즈·부착 기준을 사용한다. 같은 부위는 한 번에 한 변형만 표시한다.

## First 액션과의 호환 조건

- Tools/export_first_idle_to_unity.py는 DGN_Armature와 Body를 참조한다. 리그 이름, 본 이름, 계층, 로컬 축, 바인드 포즈, 스케일과 애니메이션 경로를 유지한다.
- CharacterTestPreviewSetup.cs는 Generic 리그를 사용한다. Humanoid 자동 리타게팅을 전제로 하지 않는다.
- FirstCrawlCorrectivePostprocessor.cs는 Body의 Crawl_Follow_L/R 블렌드셰이프를 제어한다. 새 토폴로지에서는 보정을 재제작하고 이름과 경로를 보존해야 한다. 이름만 복사해도 같은 보정이 되는 것은 아니다.
- 골격 위치를 움직이기 전에 메시 실루엣부터 조정한다. 기존 골격에서 원하는 체형이 불가능하면 해당 액션 보정 범위를 별도로 정한다.
- 걷기·4방향 달리기·점프/착지·웅크리기·포복·한손/양손 운반·던지기·전투 액션을 새 메시로 재생한다. 발 접지, 배와 허벅지, 복면과 어깨, 손과 운반물의 관통을 확인한다.

## Blender 제작 순서

1. First 원본/대기 FBX를 별도 작업 파일에 불러와 리그와 액션을 기준으로 고정한다.
2. 정면·측면 스케치로 몸통과 복면을 블록아웃한다. Mirror/Subdivision으로 둥근 실루엣을 만든다.
3. 볼·배의 조형을 다듬고, 어깨·팔꿈치·골반·무릎의 변형을 고려해 리토폴로지한다.
4. 5개 부품을 분리하고 동일 골격으로 웨이트를 전달한 뒤 관절 부위를 직접 보정한다.
5. 니트 디테일은 노멀/재질 중심으로 만들고, 실루엣에 영향을 주는 복면 테두리만 형상으로 표현한다.
6. 기존 액션을 재생하며 웨이트 및 포복 보정 셰이프를 조정한다. FBX 내보내기 후 Unity Generic 클립 바인딩까지 확인한다.

## 커스터마이징 코드의 후속 변경

AvatarAppearanceApplier는 현재 재질·텍스처·색을 적용한다. 메시 교체와 동일 본 배열 연결 기능이 필요하다. AvatarAppearance는 BodyColor/Hood/Shoes/Face로 구분하므로 Eyes와 Mouth를 독립 선택할 데이터, UI, 저장/전송 경로를 추가해야 한다. 기존 Face 데이터의 이전 규칙도 필요하다.
