# WebGL 실시간 그림자 3조건 비교 — 2026-09-10

## 결론

동일 구도 A에서 현재 그림자 유지 약 72.3FPS, 점·스폿 조명 그림자 제거 약 98.9FPS, 모든 실시간 그림자 제거 약 97.8FPS였다. 점·스폿 그림자 제거는 이 대조에서 약 37% 개선됐고, 전체 제거의 추가 이득은 관찰되지 않았다. 제품 적용 후보는 ②이며, 이번 요청은 시험이므로 영구 적용·MR·배포는 하지 않았다.

## 조건

현재 PC의 Chromium 기반 Codex 내부 브라우저, WebGL Host 1명, 로컬 진단 빌드. 빌드 실행을 마친 뒤 한 게임 탭만 열었다. 출력 캔버스 1920×1200, 브라우저 표시 영역 1280×720, 3D 배율 75%(1440×900)를 모든 조건에 고정했다. 자동 배율 조절을 진단에서만 멈췄다. 따라서 앞선 자동 해상도 실험 수치와 직접 비교하지 않는다.

①→②→③ 순서로 실행했으며, 저장 화면에서 ②의 초기 구도가 달랐음을 발견해 ②를 다시 측정했다. 이후 ① 복귀 측정은 다른 구도 B였으므로 구도 B의 기존 ②와 별도로 비교했다. 구도 간 FPS를 섞지 않았다. 각 표본은 페이지 시작 후 워밍업을 거친 30초이며 조건당 2개다. 모두 측정 종료 시 visible/focus 상태를 확인했다. 로컬 HTML의 pointer lock 우회는 제품 코드에 포함하지 않는다. 우회만으로 구도가 고정된다고 가정하지 않고 실제 저장 화면을 확인했다.

단일 진단 빌드에서 URL 조건만 변경했다. Lobby 로드 후 10초에 Light.shadows를 None으로 바꿨으며 조명 자체, 색·밝기, 게임 규칙·Host·물리·네트워크 tick은 바꾸지 않았다. 장면에서 발견된 방향광은 2개, 비방향광은 22개다. ②는 정확히 비방향광(점·스폿 등)의 그림자를 끄고 두 방향광은 유지하는 시험이다. ③은 방향광까지 모두 끈다. 베이크된 명암·SSAO·재질 명암은 제거하지 않았다.

②와 ③의 작은 차이로 전체 그림자가 없는 것이 더 느리다는 일반적 결론을 내리지는 않는다. 이 표본에서 ③의 추가 성능 이득이 확인되지 않았다는 뜻이다.

## 해석과 적용 판단

현재 로비에서는 추가 조명의 실시간 그림자 처리가 유의미한 렌더링 부담이다. 이 변경만으로 같은 장면의 성능이 개선됐으므로, 로비의 낮은 FPS를 Host 서버 성능만의 문제로 보는 것은 적절하지 않다. CPU/GPU 그림자 비용 각각의 비율이나 다른 맵의 결과까지 확정한 것은 아니다.

성능 우선 적용 후보는 ②다. 방향광 그림자는 유지할 수 있고 ③과 비슷한 FPS를 얻었다. 다만 점·스폿 조명으로 생기던 물건·캐릭터의 동적 그림자는 없어지므로 기존 화면과 완전히 같지 않다. 경기 중 시각적 단서·분위기에 미치는 영향은 별도 확인이 필요하다. 본 결과는 1인 로비이며 실제 Chrome 3~6인 경기의 99FPS 또는 끊김 완전 제거를 보장하지 않는다.

## 후속 제품 반영: 사용자가 3번 선택

현재 feature/client/lobby-render-pass-cleanup 브랜치의 WebGL 전용 URP에서 주광원·추가 광원·Soft Shadows를 모두 비활성화하고 Screen Space Shadows 기능도 끈다. 조명, SSAO, Host 및 게임 규칙은 유지한다. 그림자 설정은 선택·저장·표시만 유지하고 렌더링에는 적용하지 않는다. PC/Standalone 프로필은 변경하지 않는다. 위 측정은 고정 75% 해상도의 진단 빌드 결과이며, 이 제품 설정으로 재빌드한 후의 실측 수치가 아니다.

검증: 그림자 비활성화·자동 해상도·지원 설정 테스트 19개, 설정 UI·저장 회귀 테스트 97개 통과(총 116개). 결과: `.build/lobby-profiler/shadows-off-tests.xml`, `shadows-off-settings-tests.xml`. 이 변경 이후 WebGL 재빌드·배포는 아직 진행하지 않았다.

최신 develop `96a1d131` 병합 후 관련 EditMode 테스트 128개 통과. 결과 파일: `.build/lobby-profiler/mr-develop-tests.xml`.
