기준: develop `6cc67dae`. 브랜치: `feature/server/performance-friends`.

## 574: 직렬화 버퍼 복사 제거

압축 전에 원본 스트림을 배열로 복제하던 1회, 복원된 스트림을 배열로 복제하고 다시 읽기용 배열로 복제하던 2회를 제거했다. 기존 GZip, 직렬화 버전, 8 MiB 제한과 입력 검증은 유지한다.

[변경 전 JSON](replay-before-optimization-2026-09-07.json)과 [변경 후 JSON](replay-after-optimization-2026-09-07.json)은 동일 개발 PC에서 연속 측정했다. .NET 10.0.11, tiered compilation 비활성, 고정 시드 574, 플레이어 데이터 6개, 클립 3개, 클립당 101프레임/10초. 조건별 20회 워밍업 뒤 100회씩 3세트다. 아래는 각 세트 통계의 중앙값이며 전체 표본의 p95가 아니다.

| 물건/프레임 | 처리 | 할당 bytes/회 전 → 후 | p50 ms 전 → 후 | p95 ms 전 → 후 |
|---|---|---:|---:|---:|
| 6 | 압축 | 587,240 → 462,184 | 0.8340 → 0.6792 | 1.2932 → 1.1317 |
| 6 | 복원 | 961,298 → 711,110 | 0.9295 → 0.5831 | 1.7468 → 0.9417 |
| 32 | 압축 | 2,170,041 → 1,742,731 | 2.7103 → 2.1804 | 3.2272 → 2.5542 |
| 32 | 복원 | 3,392,617 → 2,543,360 | 3.1089 → 2.1306 | 3.9952 → 3.5014 |
| 64 | 압축 | 4,233,962 → 3,439,253 | 4.4102 → 3.7538 | 6.6828 → 4.5699 |
| 64 | 복원 | 6,465,563 → 4,877,478 | 5.3468 → 3.8411 | 7.6633 → 5.2939 |

압축 할당은 약 19~21%, 복원 할당은 약 25~26% 감소했다. 세 조건에서 입력 SHA256과 원본/압축 크기가 동일하며 압축 왕복 후 원본 byte 일치 및 잘못된 압축 입력 거절 검사를 통과했다.

현재 스레드의 managed 할당 측정으로 native 메모리와 상주 메모리는 포함하지 않는다. 에디터가 열린 개발 PC의 합성 입력 측정이므로 Unity Mono/IL2CPP, 실제 6인 경기의 Tick·FPS·송수신량 개선을 증명하지 않는다. 실제 6인 경기 프로파일링은 별도 검증 항목이다. 실행 방법은 [측정 도구](../../Tools/performance/replay/README.md)를 참고한다.

## 577 / 578: 친구 검색과 중복 조회

- 기존 정확 닉네임 검색과 요청 API를 재사용한다. 검색어 공백 제거, 대소문자·접두어 불일치 제외, 요청 대상 ID를 회귀 테스트로 확인했다.
- 검색 응답의 순서를 검사해 이전 검색이 최신 결과를 덮지 못하게 한다. 취소된 화면의 늦은 검색 성공 응답도 반영하지 않는다.
- 같은 수명 토큰의 진행 중 친구 조회는 UniTask의 AsyncLazy로 공유한다. 완료 전에 대기자 3개를 연결한 테스트에서 gateway 호출 1회를 확인했다.
- 친구 수락·삭제·상호 요청 성립 후에는 새로 조회하며 이전 응답이 최신 목록을 덮지 못하게 한다.
- 홈 초기 로드와 패널의 중복 조회를 합친다. 받은/보낸 요청 조회 중 변경이 발생하면 완료 후 재조회한다.
- FriendUiCommandsTests와 HomeProfileFriendSystemTests 30건 통과. 컴파일된 테스트를 독립 .NET 실행기로 실행하고 비동기 Task 완료까지 기다렸다. Unity 화면 또는 실제 HTTP 호출 수 측정 결과가 아니다.
- HighlightStoryTests의 직렬화 관련 3건도 독립 .NET에서 통과했다. Unity ScriptableObject가 필요한 나머지 테스트는 이 실행에 포함하지 않았다.
