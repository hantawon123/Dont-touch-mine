## 1. 정지한 물건의 불필요한 갱신 제거
커밋 470fea97. CarryableItem은 참가자의 물건 위치를 보간할 때만 FixedUpdate를 실행한다. 스크립트만 비활성화하며 Rigidbody, Collider, GameObject와 공개 상호작용 메서드는 유지한다.
검증: 새 PlayMode/씬 전환3, 물건·배치 EditMode27, 착지·받침 제거·결과 상태 복구 PlayMode6 통과. 정상 정지 구간에서 CarryableItem.FixedUpdate 호출 제거 확인.

## 2. 렌더 방식 대조: 기존 설정 유지
정적 배칭 범위 조정은 개선을 확정하지 못해 제외했다. 고정 배경은 이미 상당 부분 배칭되고 있다.
CPU 오클루전 베이크와 GPU 인스턴싱(SRP 배처 비활성화)을 각각 동일한 3개 스폰 위치 × 4방향에서 비교했다. 640×360 오프스크린 Camera.Render, 각 모드 워밍업 후3회 평균, 실행 순서를 시야마다 교대했다. 모두 12개 시야에서 픽셀 차이가0이었지만, CPU 렌더 호출 시간은 대부분 증가했다. 그러므로 새 베이크 데이터, 재질/파이프라인 설정, 실험용 배칭 코드는 원본에 적용하지 않았다.
이 시간은 GPU 실행 시간이나 WebGL FPS가 아니다. Unity 에디터/프로파일러/Single 모드 측정이며, 실험에서 효과가 없었다는 뜻이지 모든 플랫폼에서 GPU 인스턴싱이 느리다는 뜻은 아니다.

| 실험 | 기존 방식 중앙값 | 후보 방식 중앙값 | 판단 |
|---|---:|---:|---|
| 가림 처리 | 10.425ms | 12.249ms | 미적용 |
| GPU 인스턴싱 | 9.488ms | 12.511ms | 미적용 |

검증 주의: 맵 진단 직후 같은 프로세스에서 기존 물리 단위 시험을 실행했을 때, 남아 있는 맵 충돌체가 시험에 간섭하여 한 건 실패했다. 물리 시험을 독립 실행한 결과는6/6 통과했다. 통합 진단과 독립 물리 시험을 구분한다.
