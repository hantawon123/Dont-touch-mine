# 달빛 도둑 인트로 — 구현 스펙

5초 루프 / 2D / 조명 있음 / 조명은 화면 가운데 고정 / 그림자 없음 / 뒤에 달 / 울퉁불퉁한 바닥
도둑 3인이 **화면 오른쪽 → 왼쪽**으로 달려 지나간다.

이 문서 하나로 다른 환경에서 그대로 재현할 수 있도록 수치를 전부 적어 두었습니다.
§1~§5 는 엔진과 무관한 스펙, §6 은 Unity 구현 절차, §7 은 다른 엔진으로 옮길 때의 요약입니다.

## 0. 요구사항 → 구현 매핑

| 받은 요구사항 | 구현 |
|---|---|
| 2D | 직교(Orthographic) 카메라 + 스프라이트만 사용. 3D 오브젝트 없음 |
| 조명 있어야 함 | 전역광 1개 + 달 위치의 점광원 1개 |
| 조명 위치 가운데 고정, 도둑이 뛰어 지나감 | 점광원은 `(0, -1.6)` 에 **고정**. 움직이는 것은 도둑 3인뿐 |
| 그림자 없이 | 그림자 캐스터를 어디에도 두지 않음. 실루엣은 조명 영향을 받지 않는 Unlit 머티리얼 |
| 뒤에 달 | 달은 도둑보다 뒤 레이어. 지면선에 살짝 걸치도록 낮게 배치 |
| 울퉁불퉁한 땅 | 가로 심리스 타일 2겹(근경 검정 / 원경 남색)으로 깊이감 |

추가로 정한 것: **오른쪽 → 왼쪽 이동**, **끊김 없는 5초 루프**.

## 1. 좌표계와 화면 규격

모든 수치의 기준입니다. 이것만 맞추면 나머지 값이 전부 따라옵니다.

```
해상도          1920 × 1080 (16:9)
1 월드 유닛     = 100 px      (Unity 기준 Pixels Per Unit = 100)
카메라          Orthographic, Size 5.4
  -> 보이는 범위 가로 19.2 유닛 × 세로 10.8 유닛
  -> 화면 좌하단 (-9.6, -5.4) ~ 우상단 (9.6, 5.4)
배경색          #030813
```

화면 픽셀 ↔ 월드 좌표 변환:

```
world_x = (px_x - 960) / 100
world_y = 5.4 - px_y / 100
```

해상도가 달라도 **비율(16:9)과 Ortho Size 5.4** 만 유지하면 구도는 그대로입니다.

## 2. 씬 레이아웃

### 2-1. 배치표

| 오브젝트 | 위치 (world) | 크기 | 그리는 순서 | 색 / 조명 |
|---|---|---|---|---|
| 달무리 `moon_glow` | `(0, -1.60)` | 지름 16.50 유닛 | 0 (제일 뒤) | 흰색, 알파 약 42%, Unlit |
| 달 원반 `moon_disc` | `(0, -1.60)` | 지름 5.20 유닛 | 10 | 흰색, Unlit |
| 원경 바닥 `ground_back` | 중심 `(0, -3.468)` | 가로 타일 28 × 세로 2.6 | 20 | `#0D162A`, **Lit** |
| 도둑 3인 | `y = -3.60` (발바닥) | §3 참조 | 30 | 순수 검정, Unlit |
| 근경 바닥 `ground_front` | 중심 `(0, -3.856)` | 가로 타일 24 × 세로 3.2 | 40 | 순수 검정, Unlit |
| 비네트 `vignette` | `(0, 0)` | 19.2 × 10.8 | 90 (제일 앞) | 검정, Unlit |

### 2-2. 지면선

캐릭터가 딛는 선은 **`y = -3.60`** (화면 위에서 900px) 한 곳입니다.

바닥 텍스처는 이미지 위에서 42% 지점이 지면 윗면입니다. 그래서 스프라이트 중심 y 는

```
중심 y = 지면선 - 세로크기 × (0.5 - 0.42)
```

- 근경(세로 3.2): `-3.60 - 3.2×0.08 = -3.856`
- 원경(세로 2.6, 지면선 `-3.26`): `-3.26 - 2.6×0.08 = -3.468`

근경 바닥의 아래쪽 끝은 `-5.456` 으로 화면 하단 `-5.4` 보다 아래라 빈틈이 생기지 않습니다.

### 2-3. 달 위치

달 중심 `(0, -1.60)`, 지름 5.20 → 아래쪽 끝이 `-4.20`. 지면선 `-3.60` 보다 아래이므로
**달의 아래쪽 약 12% 가 지평선에 묻힙니다.** 이게 레퍼런스의 "달이 뜨는/지는" 구도입니다.

달을 더 크게/낮게 하고 싶으면 `Moon` 오브젝트의 y 만 옮기세요. 조명도 같이 따라갑니다.

## 3. 캐릭터 스펙

### 3-1. 원화 비율 (전신 높이 200 기준)

원화(뜨개 두건 + 둥근 귀 2개, 짧고 통통한 몸, 큰 둥근 신발, 등에 멘 보따리)를 실측해 환산한 값입니다.

| 부위 | 치수 | 전체 대비 | 메모 |
|---|---|---|---|
| 전신 (귀 끝 ~ 발바닥) | 200 | 100% | |
| 머리(두건) 지름 | 84 | 42% | **이 큰 머리가 캐릭터의 정체성.** 절대 줄이지 말 것 |
| 귀 지름 | 29 | 14.5% | 머리 중심에서 반지름×1.10 거리, 좌 -38° / 우 +36° |
| 몸통 높이 (어깨~골반) | 37 | 18.5% | |
| 몸통 폭 | 50 | 25% | 어깨 반지름 26 / 골반 반지름 24 |
| 다리 길이 (골반~발바닥) | 56 | 28% | 허벅지 23 + 종아리 22 + 신발 |
| 다리 두께 | 22 | 11% | |
| 신발 | 43 × 24 | | 다리 두께보다 확실히 커야 캐릭터 느낌이 난다 |
| 팔 | 위팔 25 / 아래팔 22, 두께 17 | | |
| 보따리 지름 | 62 | 31% | 어깨 기준 뒤로 44, 아래로 15 |

### 3-2. 원화 → 실루엣 변환 시 바뀐 점 (중요)

원화는 색이 있어서 머리·보따리·몸통이 구분됩니다. **검은 실루엣 하나로 만들면 그게 전부 한 덩어리로 뭉개집니다.**
그래서 아래 두 가지를 원화와 다르게 조정했습니다. 나중에 원화 비율로 되돌리면 다시 뭉개지니 주의하세요.

| 항목 | 원화 | 실루엣 | 이유 |
|---|---|---|---|
| 보따리 지름 | 72 | **62** | 원래 크기면 몸통과 뒷다리를 통째로 덮어버림 |
| 보따리 위치 | 어깨 바로 뒤, 높음 | **어깨보다 15 아래, 뒤로 44** | 머리와 보따리 사이에 오목한 노치를 만들어 두 덩어리를 분리 |

팔도 마찬가지입니다. 원화에서는 한 팔이 보따리 끈을 쥐고 몸 앞에 붙어 있는데, 실루엣에서는 몸통에 파묻혀 사라집니다.
그래서 **양팔 모두 자유롭게 흔들도록** 바꿨습니다. 움직임도 이쪽이 더 잘 읽힙니다.

### 3-3. 3인 변형

같은 캐릭터의 체격 차이입니다. 종족이 달라 보이면 안 됩니다.

| 이름 | 전체 배율 | 숙인 각도 | 머리 | 귀 | 보따리 | 화면상 키 | 무리 위치 |
|---|---|---|---|---|---|---|---|
| C | 1.09 | 5° | 0.96 | 0.94 | 1.12 | 3.00 유닛 (300px) | 선두(제일 왼쪽) |
| A | 1.00 | 7° | 1.00 | 1.00 | 1.00 | 2.72 유닛 (272px) | 중간 |
| B | 0.88 | 10° | 1.05 | 1.10 | 0.86 | 2.40 유닛 (240px) | 후미(제일 오른쪽) |

작은 개체일수록 머리·귀를 키우고 보따리를 줄여서 "어린 쪽"으로 읽히게 했습니다.

### 3-4. 스프라이트 파일 규격

```
프레임 크기       256 × 256 px
프레임 수         8
파일 형태         Sprites/Frames/thief_X_run_0.png ~ _7.png  (개별 파일)
                  Sprites/thief_X_run.png 은 참고용 시트 — 엔진에서는 쓰지 않음
방향              왼쪽을 향함 (좌우 반전 불필요)
색                순수 검정 + 알파. 조명이 닿아도 색이 변하면 안 됨
발바닥 위치       프레임 위에서 241px 지점
피벗              (0.5, 0.059)   ← (256-241)/256
```

> 프레임을 **개별 PNG 로** 나눠둔 이유: 스프라이트 시트를 자르는 API 는 Unity 버전마다 바뀌고
> (Unity 6 에서 `TextureImporter.spritesheet` 는 deprecated) 다른 엔진에는 아예 없습니다.
> 개별 파일이면 "각각을 Single 스프라이트로 임포트" 하나로 끝나서 어디서든 동일하게 동작합니다.

PNG 안에서 캐릭터가 실제로 차지하는 세로 픽셀 (배율 계산에 필요):

| 파일 | 캐릭터 픽셀 높이 | 화면상 목표 키 | 트랜스폼 배율 |
|---|---|---|---|
| `thief_A_run_*.png` | 205 | 2.72 유닛 | **1.327** |
| `thief_B_run_*.png` | 183 | 2.40 유닛 | **1.311** |
| `thief_C_run_*.png` | 220 | 3.00 유닛 | **1.364** |

> 배율 = 목표 키 ÷ (픽셀 높이 ÷ 100). 스프라이트를 다시 뽑아 높이가 달라지면 이 표도 같이 고쳐야 합니다.

## 4. 애니메이션 스펙

### 4-1. 8키 러닝 사이클

각도는 **아래 방향을 0°, 진행 반대쪽(그림 기준 오른쪽)을 +** 로 잰 값입니다(도).
좌우 반전 전 기준이므로, 왼쪽으로 달리는 최종 결과에서는 부호가 뒤집혀 보입니다.

| 프레임 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 허벅지 | 30 | 10 | −12 | −32 | −6 | 22 | 34 | 36 |
| 무릎 굽힘 | 10 | 38 | 16 | 6 | 86 | 96 | 62 | 26 |
| 어깨 | −40 | −14 | 16 | 40 | 34 | 8 | −22 | −42 |
| 팔꿈치 굽힘 | 70 | 84 | 92 | 80 | 70 | 84 | 92 | 80 |

- 종아리 각도 = 허벅지 − 무릎굽힘 (무릎은 항상 뒤로만 접힘)
- 아래팔 각도 = 어깨 + 팔꿈치굽힘
- 반대쪽 팔다리는 **4프레임(반 사이클) 어긋난** 같은 값
- 발끝 각도 = 종아리각 × 0.3 + 8, 신발은 발목에서 앞쪽으로 튀어나온 타원

### 4-2. 상하 바운스

사이클당 2회 튑니다(양발이 각각 지면을 찰 때).

```
bob(p) = -2.0 + 3.4 × cos(4π·p)      # p = 사이클 진행도 0~1, 단위는 설계단위
```

보따리는 이 값의 25% 만 따라 움직여 살짝 늦게 출렁입니다.

### 4-3. 재생 속도와 위상

```
재생 속도   19.2 fps   (= 8프레임 × 12사이클 ÷ 5초)
프레임 번호 = (floor(t × 19.2) + 위상오프셋) mod 8
위상오프셋  C = 3,  A = 6,  B = 1
```

위상오프셋을 서로 다르게 주는 게 중요합니다. **셋 다 0이면 발이 똑같이 맞아서 로봇처럼 보입니다.**

## 5. 이동과 5초 루프

### 5-1. 이동 공식

```
랩 폭      loopWidth  = 27.2 유닛   (화면 폭 19.2 + 좌우 여유 8)
속도       speed      = 27.2 ÷ 5 = 5.44 유닛/초
등장 위치  spawnEdge  = +13.4      (화면 오른쪽 끝 9.6 보다 바깥)
방향       direction  = -1         (오른쪽 → 왼쪽)

x(t) = 13.4 - Repeat(startOffset + 5.44·t, 27.2)
y    = -3.60  (고정)

startOffset :  C = 5.45,  A = 2.85,  B = 0.00      # 클수록 앞(왼쪽)
```

`x` 는 `+13.4` 에서 `-13.8` 까지 내려간 뒤 다시 `+13.4` 로 되돌아옵니다.
누적 이동이 아니라 **시간으로부터 위치를 직접 계산**하므로 프레임레이트가 흔들려도 위치가 밀리지 않습니다.

### 5-2. 루프가 끊기지 않는 조건

두 가지가 **동시에** 맞아야 합니다.

```
① 위치 :  speed × 5초 = loopWidth        ->  5.44 × 5 = 27.2   ✓
② 자세 :  fps × 5초 ÷ 8 = 정수 사이클     ->  19.2 × 5 ÷ 8 = 12  ✓
```

둘 중 하나라도 어긋나면 5초마다 도둑이 툭 튑니다.
**속도나 크기를 바꿀 때는 반드시 이 두 식을 같이 맞추세요.**

예를 들어 조금 더 빠르게 하고 싶다면 `loopWidth` 를 32.0 으로 올리고 `speed = 32.0 ÷ 5 = 6.4`,
그리고 보폭이 맞도록 `fps` 를 `8 × 14 ÷ 5 = 22.4` (14사이클)로 같이 올리는 식입니다.

### 5-3. 보폭 검산

```
한 사이클당 전진 거리 = speed ÷ (사이클/초) = 5.44 ÷ 2.4 = 2.27 유닛
```

캐릭터 키가 2.40~3.00 유닛이므로 한 사이클(양발 2걸음)에 자기 키의 0.8배 정도를 갑니다.
**캐릭터를 크게 키우면서 속도를 그대로 두면 발이 미끄러져 보입니다.**

## 6. Unity 구현

### 6-1. 조명 모드 두 가지 — 먼저 고를 것

**`Light2D` 는 URP 의 2D Renderer 에서만 동작합니다.** 3D 게임 프로젝트는 보통 Universal Renderer(3D용)를
쓰기 때문에, 거기에 Light2D 를 넣어봐야 아무 일도 일어나지 않습니다. 그래서 모드를 둘로 나눠뒀습니다.

| | A. 스프라이트 전용 | B. Light2D 사용 |
|---|---|---|
| 조건 | 없음. 어떤 파이프라인에서도 동작 | URP 렌더러 목록에 **2D Renderer** 가 있어야 함 |
| 결과물 | 프리뷰 영상과 **동일** | 영상 + 원경 바닥에 실제 빛 그라데이션 |
| 리스크 | 없음 | 3D 프로젝트의 렌더 파이프라인을 건드려야 함 |

> 프리뷰로 보신 그 영상에는 **실시간 조명이 하나도 안 들어가 있습니다.** 달빛처럼 보이는 건 전부
> `moon_glow` 스프라이트예요. 그래서 A 모드만으로도 영상과 같은 그림이 나옵니다.
> 받은 스펙의 "조명 있어야 한다" 를 문자 그대로 맞춰야 한다면 B 로 가세요.

**B 를 쓰려면** (3D 프로젝트 기준, 기존 렌더링은 건드리지 않는 방법):

1. `Assets > Create > Rendering > URP 2D Renderer` 로 **2D Renderer Data** 생성
2. 쓰고 있는 URP Asset(예: `Assets/Settings/PC_RPAsset.asset`)의 **Renderer List** 에 그걸 추가
   → 기존 3D 렌더러는 index 0 그대로 두고, 2D 렌더러가 index 1 로 붙습니다
3. `Tools > Intro > 3)` 메뉴를 쓰면 인트로 카메라의 Renderer 를 자동으로 그 index 로 맞춰줍니다

`Default Renderer Index` 는 0 그대로 둬야 본 게임 렌더링이 안 바뀝니다.
잘 모르겠으면 `Tools > Intro > 진단` 을 먼저 눌러보세요. 현재 렌더러 목록을 콘솔에 찍어줍니다.

파이썬 생성기와 프리뷰 영상은 `Assets/` 밖의 `docs/intro/tools/` 에 있어서 Unity 가 임포트하지 않습니다.
생성기는 실행 위치와 무관하게 `Assets/_Game/Content/UI/Intro/` 로 PNG 를 출력합니다.

**색공간 주의.** 프리뷰 영상은 sRGB(감마) 공간에서 알파 합성한 결과입니다. 이 프로젝트는
`Project Settings > Player > Color Space = Linear` 라서 같은 `moon_glow.png` 를 그대로 쓰면
알파가 리니어 공간에서 섞여 달무리 중심이 109→173, 중간부가 40→107 로 훨씬 밝고 넓게 퍼집니다.
그래서 `bake_linear.py` 가 알파에 sRGB→Linear 변환을 미리 먹인 `moon_glow_linear.png` 를 만들고,
`IntroSceneBuilder` 는 색공간이 Linear 면 자동으로 그 파일을 씁니다 (Gamma 프로젝트면 원본).
배경이 거의 검정이라 이 보정으로 영상과 1~2 단계 안에서 일치합니다.

스크립트 4개는 모두 **URP 타입을 직접 참조하지 않습니다.** Light2D 는 리플렉션으로만 다루기 때문에
URP 가 없는 프로젝트에 넣어도 컴파일 에러가 나지 않습니다.

### 6-3. 자동 구성

빈 씬을 하나 만들고(`File > New Scene > Basic 2D` 또는 Empty) 메뉴를 실행합니다.

1. `Tools > Intro > 1) 스프라이트 임포트 설정`
   PPU 100 / 압축 없음 / Full Rect / 바닥만 Repeat, 도둑 프레임 24장은 피벗 `(0.5, 0.059)`
2. 둘 중 하나
   - `Tools > Intro > 2) 씬 구성 — 스프라이트 전용 (파이프라인 무관)`
   - `Tools > Intro > 3) 씬 구성 — Light2D 사용 (2D Renderer 필요)`
     2D Renderer 가 없으면 경고를 남기고 자동으로 2) 와 같은 결과로 폴백합니다
3. **Play** — 5초 한 바퀴를 다 돌면 `Home` 씬으로 넘어간다. 스킵은 없다.
   4.3초부터 0.7초 동안 배경색으로 페이드아웃되고, 완전히 어두워진 5.0초에 Home 을 로드한다
4. `Tools > Intro > 4) 씬 저장 + Build Settings 맨 앞에 등록`
   `Assets/_Game/Content/Scenes/Intro.unity` 로 저장하고 Build Settings index 0 에 넣는다.
   빌드는 인트로 → Home 순서로 시작한다.

**에디터에서 Home 을 Play 했을 때.** `IntroPlayFromHome`(에디터 전용)이 활성 씬이 Home 이면
Play 시작 씬을 인트로로 바꿔 준다. 그래서 팀 습관대로 Home 에서 Play 를 눌러도 인트로 → Home 으로 보인다.
Lobby, Playground 등 다른 씬에서 Play 하면 건드리지 않는다.
`Tools > Intro > Home 에서 Play 하면 인트로 먼저` 로 켜고 끌 수 있고, 이 설정은 컴퓨터마다 따로 저장된다(기본 ON).
인트로 씬이 아직 저장돼 있지 않으면 평소처럼 Home 이 바로 뜬다.

종료 처리는 `IntroLoopController`(autoFinish, loopCount=1, allowSkip=false) 와
`IntroSceneExit`(onIntroFinished → `Home` 단독 로드) 가 맡는다. 무한 루프로 되돌리려면
`IntroScene` 오브젝트의 `Auto Finish` 를 끄면 된다.

인트로 카메라는 `Depth = 10` 으로 만들어져서, 씬에 다른 카메라가 있어도 인트로가 위에 그려집니다.

### 6-4. 수동 구성 (또는 자동 결과 검증)

**카메라** — Orthographic / Size `5.4` / Position `(0, 0, -10)` / Solid Color `#030813`

**전역광 `Global Light 2D`**

| 항목 | 값 |
|---|---|
| Light Type | Global |
| Color | `#5A7FB4` |
| Intensity | `0.16` |

**달빛 `Point Light 2D`** — `Moon` 의 자식, **위치 고정**

| 항목 | 값 |
|---|---|
| Light Type | Point |
| Position | `(0, -1.6)` |
| Color | `#FFF6E0` |
| Intensity | `2.4` |
| Inner Radius | `1.2` |
| Outer Radius | `11.0` |
| Falloff Intensity | `0.7` |

**스프라이트 배치** — §2-1 표 그대로. 바닥 2개는 Draw Mode `Tiled` + Tile Mode `Continuous`.

**그림자를 없애는 법**

1. `ShadowCaster2D` 를 **어디에도 붙이지 않습니다.** URP 2D 그림자는 이 컴포넌트가 있어야만 생깁니다.
2. 도둑과 근경 바닥의 머티리얼은 `Sprite-Unlit-Default` + Color 검정.
   `Sprite-Lit-Default` 를 쓰면 달빛을 받아 실루엣이 회색으로 떠버립니다.

원경 바닥만 `Sprite-Lit-Default` 를 씁니다. 달빛이 닿는 가운데가 은은하게 밝아지면서 깊이가 생깁니다.
조명을 실제로 쓴 효과가 눈에 보이는 곳이 여기입니다.

### 6-5. 스크립트

| 파일 | 역할 |
|---|---|
| `IntroLoopController` | 인트로 공통 시계. 나머지 스크립트가 전부 이 시간을 참조해 루프가 정확히 맞는다 |
| `ThiefRunner` | §5-1 공식으로 x 계산 |
| `SpriteSheetAnimator` | §4-3 공식으로 프레임 선택. `Animator` 없이 동작 |
| `MoonGlow` | 달빛 세기와 달무리 크기를 ±5% 로 아주 미세하게 호흡시킴. 위치는 건드리지 않음 |
| `IntroSceneExit` | `IntroLoopController.onIntroFinished` 를 받아 `nextSceneName`(기본 Home) 을 단독 로드. 중복 로드 방지 |
| `IntroFadeOut` | 마지막 0.7초 동안 화면 전체를 배경색 `#030813` 으로 SmoothStep 페이드. 종료 시점에 완전 불투명 → Home 로드. 텍스처 없이 `whiteTexture` 사용, 정렬 100 |

### 6-6. 게임 본편으로 넘기기

`IntroLoopController` 인스펙터에서 `Auto Finish` 체크 + `Loop Count = 1` → 5초 뒤 `onIntroFinished` 호출.
`Allow Skip` 을 켜면 아무 키/클릭으로 즉시 스킵됩니다.

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;

public class IntroExit : MonoBehaviour
{
    public string nextScene = "Main";
    public void GoNext() => SceneManager.LoadScene(nextScene);   // onIntroFinished 에 연결
}
```

### 6-7. 선택 사항

- **블룸** — 달이 진짜 빛나 보이는 건 거의 이것 하나 차이입니다.
  URP Asset 에서 Post Processing 활성화 → 씬에 Global `Volume` 추가 → `Bloom` 오버라이드
  (Threshold `0.8` / Intensity `1.2` / Scatter `0.75`). 쓰면 `vignette` 스프라이트는 꺼도 됩니다.
- **흙먼지** — `Ground_Front` 앞에 작은 검정 파티클(Simulation Space = World)을 두면 지나갈 때 먼지가 납니다.

## 7. 다른 엔진으로 옮길 때

엔진에 의존하는 부분은 §6 뿐입니다. 아래 5가지만 재현하면 결과가 같습니다.

1. **화면 규격** — 16:9, 세로 10.8 유닛이 보이게. §1 의 변환식으로 픽셀 좌표를 바로 쓸 수도 있습니다.
2. **그리는 순서** — 달무리 → 달 → 원경바닥 → 도둑 → 근경바닥 → 비네트 → 페이드(마지막 0.7초만)
3. **조명** — 화면 중앙 `(0, -1.6)` 에 고정된 반지름 11 유닛의 점광원 + 약한 전역광.
   실루엣은 조명 계산에서 제외(= Unlit)해야 검정으로 유지됩니다.
   조명 기능이 없는 환경이면 달무리 스프라이트만으로도 그림은 거의 같게 나옵니다.
4. **애니메이션** — §4 의 8키 각도표와 19.2fps
5. **루프 조건** — §5-2 의 두 등식

웹(Canvas/WebGL)이라면 `docs/intro/tools/` 의 파이썬 렌더러(`render_preview.py` 와 동일한 계산)를
그대로 JS 로 옮기면 됩니다. 합성 순서와 수치가 전부 같습니다.

## 8. 트러블슈팅

| 증상 | 원인 / 해결 |
|---|---|
| 도둑이 회색으로 보임 | 머티리얼이 `Sprite-Lit-Default`. Unlit + Color 검정으로 |
| 화면이 전부 새까맣게만 나옴 | URP Asset 이 Graphics 설정에 안 잡혔거나 2D Renderer 가 아님 |
| 바닥 이음매에 세로줄 | 임포터 Wrap Mode `Repeat`, Mesh Type `Full Rect` |
| 5초마다 도둑이 툭 튐 | §5-2 의 두 등식 중 하나가 깨짐 |
| 발이 땅에 안 붙거나 떠 있음 | 피벗이 `(0.5, 0.047)` 이 아님 |
| 도둑 3명이 똑같이 움직임 | `phaseOffset` 이 전부 같음. 3 / 6 / 1 로 |
| 조명이 도둑을 따라 움직임 | 점광원이 도둑의 자식으로 들어감. `Moon` 아래로 |
| Light2D 를 넣었는데 아무 변화가 없음 | 프로젝트가 3D용 Universal Renderer 를 쓰는 중. §6-1 참고 |
| 인트로가 다른 카메라에 가림 | 인트로 카메라의 `Depth` 를 더 높게 |
| 도둑 프레임을 못 찾는다는 에러 | `Sprites/Frames/` 24장이 있는지 확인 후 `1)` 메뉴 재실행 |
| 도둑이 왼쪽→오른쪽으로 감 | `direction` 이 `+1`. `-1` 로 (스프라이트는 이미 왼쪽을 보게 그려져 있음) |
| 발이 미끄러져 보임 | 캐릭터를 키운 만큼 `speed` 를 안 올림. §5-3 참고 |
| 머리와 보따리가 한 덩어리로 뭉개짐 | 보따리를 원화 크기·위치로 되돌린 경우. §3-2 참고 |

## 9. 에셋 재생성

`docs/intro/tools/` 의 파이썬 스크립트로 PNG 를 다시 뽑을 수 있습니다.

```bash
pip install pillow numpy
python gen_thief.py    # 도둑 3종 스프라이트 시트
python gen_bg.py       # 달 / 달무리 / 바닥 타일 / 비네트 (+ Linear 용 달무리 자동 생성)
python bake_linear.py  # Linear 색공간용 달무리만 다시 만들 때
```

**`gen_thief.py`**

- 상단의 `THIGH` / `KNEE` / `SHLDR` / `ELBOW` 배열이 §4-1 의 8키 사이클입니다.
- `draw_thief()` 안의 "설계 치수" 블록이 §3-1 의 비율입니다.
- 맨 아래 `VARIANTS` 에서 체격을 조절합니다. 항목을 추가하면 4명 이상으로도 늘릴 수 있습니다
  (`IntroSceneBuilder` 의 `Cast` 와 `CharPixelHeight` 에도 같이 추가).
- 마지막에 `FLIP_LEFT_RIGHT` 로 좌우 반전해 **왼쪽을 보는** 스프라이트를 출력합니다.
  오른쪽으로 달리게 하려면 이 한 줄을 지우고 `ThiefRunner.direction` 을 `+1` 로 바꾸세요.

**`gen_bg.py`**

- `ground()` 의 `amp` 를 올리면 바닥이 더 울퉁불퉁해집니다.
  파형 주파수가 전부 정수라 가로 심리스가 유지됩니다.
- `moon_glow()` 의 `power` 를 올리면 달무리가 더 좁고 날카로워집니다.

> 도둑 PNG 의 캐릭터 세로 픽셀이 바뀌면 §3-4 의 표와 `IntroSceneBuilder.CharPixelHeight` 를 같이 고쳐야
> 화면상 키가 맞습니다. 값은 알파 채널의 바운딩 박스로 구합니다.
