## 현재 실행 상태와 사용

- 서비스: `d205-game-release-test.service`
- EC2 경로: `/home/ubuntu/d205-game-release-test`
- 현재 릴리스: `rollout-v2`, 게임 버전: `988-rollout-v2`
- 접속: `http://localhost:4291/` → 현재 준비된 릴리스로 이동
- EC2 웹은 loopback만 사용하며 이 PC의 SSH 터널로 접속한다. 공개 포트·Jenkins·운영 백엔드는 변경하지 않았다.
- 테스트 호스트와 게임 프로세스 전체 CPU 상한 2 vCPU 상당, 메모리 상한 5 GiB. 호스트 전체의 20분 제한은 없다. 현재는 부팅 자동 시작을 설치하지 않은 transient 서비스다.
- 구형 단발 서비스 `d205-game-988-trial.service`는 inactive 확인.
- 이 PC 에디터의 로컬 선택만 현재 버전으로 갱신했다. Play 모드를 다시 시작하면 적용된다.

버전별 주소에서 새로고침하면 같은 버전을 계속 사용한다. 새 버전을 열려면 루트 주소 `http://localhost:4291/`로 다시 접속한다. 이미 방이 만들어져 있으면 새 방 대신 같은 방을 찾아 참가한다.

## 범위와 남긴 항목

이번 교체 시험은 테스트 규모의 서버 준비·라우팅·프로세스 보존과 실제 WebGL 방 생성·퇴장·재생성을 확인했다. 진행 중인 별도 PC 6인 경기에서의 교체, 100~200명 수용량, 물리 서버 간 경기 상태 이전은 검증하거나 구현하지 않았다. 서버 자체 장애·네트워크 단절·비호환 DB 변경까지 무중단으로 만드는 기능도 아니다.

사용자의 마지막 지시에 따라 팀 공통 에디터 기본 버전을 추가하려던 변경은 되돌렸다. 팀원이 pull만 하면 모든 환경에서 즉시 실행된다는 판정은 하지 않는다. 팀원 실행 환경은 다음 논의로 남겼다. 기존에 사용자가 성공을 확인한 에디터 로컬 접속 수정은 유지했다.

창모드 마우스 재클릭 문제는 사용자가 보류한 상태를 유지했다. 기존 presence 401 문제와 서로 다른 PC의 6인 경기 검증도 이 작업으로 완료 처리하지 않았다. MR·push는 하지 않았다.

실행·교체·롤백·이전 절차는 저장소 `Tools/network/server-flow/release-host.md`에 기록했다.
