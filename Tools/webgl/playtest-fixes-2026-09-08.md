# WebGL 플레이 테스트 수정

기준: develop `6c5efaa8`, 분석 당시 공개 빌드 `ffae4c75`.
작업 브랜치: `feature/client/webgl-playtest-fixes`.

## 변경

- 일반 텍스트 TMP 입력창에 HTML 입력 연동 적용. 브라우저가 한글 조합을 처리하고, 확정 문자열은 기존 입력창의 변경 이벤트로 전달한다. 숫자/PIN 및 TMP 문자 검증기를 사용하는 입력창은 기존 TMP 입력 경로를 유지한다.
- 조합 확정 Enter와 제출 Enter 구분, 붙여넣기, 입력창 교체/파괴 시 늦은 콜백 무시, 키보드 캡처 복구.
- 로비 방 제목의 마지막 legacy InputField를 TMP로 통일.
- 브라우저 입력 취소를 Unity Cancel 이벤트로 전달하고 채팅의 게임 입력 잠금 해제. 초안은 보존한다.
- 전체화면 대상을 canvas에서 container로 변경하여 HTML 입력창도 표시.
- 게임 조작이 허용된 상태에서 캔버스를 클릭하면 브라우저 사용자 제스처 안에서 커서 잠금 요청. 메뉴/텍스트 입력 중에는 요청하지 않는다.
- 네트워크 플레이어는 비활성 상태에도 권한 명령 경로를 유지하여 로컬 전용 집기로 빠지지 않는다.
- 동일 버전의 서버 스냅샷에서도 소지 상태가 어긋나면 0.5초 간격으로 복구. 이미 적용한 버전보다 오래된 스냅샷은 재적용하지 않는다.
- 놓기/배치/던지기 거절 시 해당 사용자에게 경고와 물건 상태 재발행. 서버의 거리·소유권·페이즈 검증은 유지한다.

## 확인 범위

- Unity 6000.3.22f1 격리 복사본의 상호작용 회귀 테스트 116개 통과.
- 추가 채팅 취소·설정 Presenter·소지 복구 회귀 테스트 24개 통과(앞선 검사와 일부 중복).
- WebGL 조건부 코드 활성화, UNITY_EDITOR 제외한 Game.Client C# 컴파일 통과. IL2CPP 링크/실제 게임 WebGL 실행 검증을 대신하지 않는다.
- `node Tools/webgl/test_browser_input.cjs`: 조합 이벤트, Enter, 붙여넣기, 값 보정, 이전 입력창 이벤트, 배치 좌표, 커서 재획득 검사 통과.
- 실제 Chromium 브라우저의 별도 테스트 페이지에서 한글 전달·제출 및 전체화면 컨테이너 안 입력 확인. 도구의 Unicode 입력이므로 Windows 한/영 키에 의한 실제 IME 조합 검증과 구분한다.
- 로컬 Ubuntu WSL에서 `python3 Tools/webgl/test_publish.py` 통과. 전체화면 변환과 기존 게시 순서·롤백 검사 포함.
- 로컬 WebGL IL2CPP 빌드 성공 및 브라우저 게임 홈 화면 로딩 확인. 이후 숫자/사용자 정의 검증 입력창 제외와 전체 선택 보존을 보완했으며, 이 마지막 보완은 C# 컴파일 및 브라우저 브리지 테스트로 확인한다.

## 실제 게임에서 남은 검증

공개 빌드에는 아직 이 변경이 없다. 이 문서는 4인 게임에서 버벅임이 개선됐다는 결과 보고가 아니다.

1. 검증 빌드에서 닉네임, 방 생성/수정, 친구 검색, 채팅의 한/영 전환·조합 중 Enter·Esc·붙여넣기 확인. 전체화면/창모드 모두 확인.
2. 호스트와 클라이언트에서 집기→던지기→배치→놓기, Esc/채팅/포커스 이탈 후 복귀, 기절 및 페이즈 전환 후 소지 상태 확인.
3. `?perf=1`로 접속하여 오른쪽 성능 측정 패널에서 구간별 30초 기록. 이 파라미터는 `/play/` 리다이렉트에도 보존한다.
4. 각 플레이어가 같은 조건으로 로비/숨기기/찾기를 측정하고 결과 JSON과 역할(Host/Client), 인원, 창모드/전체화면을 함께 기록한다. 포커스 이탈 또는 씬 변경이 있으면 `interrupted: true`이므로 비교에서 제외한다.

기록값: Unity Update 프레임의 평균 FPS, p50/p95/p99/최대 프레임 시간, 50ms 초과 프레임 수, GC 횟수, 관리 힙, 실제 렌더 해상도, 품질, GPU, 빌드와 씬. 서버 전송 없이 페이지에만 출력하며 정상 접속에서는 측정하지 않는다. GC 수치가 WebGL 런타임에서 제공되지 않을 가능성도 있으므로 프레임 시간과 함께 해석한다.

렌더링 병목과 네트워크/Host 병목은 이 수치만으로 확정하지 않는다. CPU/GPU 프로파일과 Host/Client 동시 기록을 대조한 뒤 최적화할 항목을 선택한다. 그래픽 품질, 프레임 제한, 물리 틱, 서버 모드는 변경하지 않았다.

## 복구

이 브랜치의 변경만 되돌리면 기존 입력·소지 상태 반영으로 복귀한다. 씬/프리팹과 `[Networked]` 필드 레이아웃은 변경하지 않았다. RPC가 추가되므로 검증 방의 참여자는 모두 같은 빌드를 사용한다.
