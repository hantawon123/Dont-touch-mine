# 에디터 개발 서버로 함께 테스트

개발자 한 명의 Unity 에디터가 기존 Dedicated Server 역할을 실행하고, 팀원들은 에디터 클라이언트로 같은 방에 접속한다. 서버·WebGL 빌드나 EC2 갱신을 기다리지 않는다. Photon과 기존 계정 인증 백엔드는 계속 사용하므로 인터넷 연결은 필요하다.

## 실행 순서

1. 모두 같은 브랜치·커밋과 필요한 로컬 수정 사항을 맞춘다. Unity 버전은 프로젝트에 지정된 `6000.3.22f1`을 사용한다.
2. 각자 `Game > Network > Development Server`를 연다.
3. 함께 테스트할 사람끼리 같은 6자리 테스트 코드(예: `DEV001`)를 입력한다. 다른 테스트 그룹은 다른 코드를 사용한다.
4. 서버 담당 한 명이 **개발 서버로 Play**를 누르고 창의 **준비됨** 또는 Console의 `[Server] Ready`를 확인한다.
5. 플레이할 팀원은 **개발 클라이언트로 Play**를 누른다. 첫 사람은 **방 만들기**, 나머지는 **게임 찾기**로 같은 방에 참가한다.

현재 방 하나에 최대 6명이 플레이한다. 서버 에디터는 플레이어 수에 포함되지 않는다. 같은 테스트 코드로 서버 두 개를 동시에 열지 않는다.

서버는 한국(`kr`) 지역을 사용한다. 테스트 코드와 제품 버전으로 개발용 Photon 접속 영역을 분리하므로 EC2 방이나 다른 개발 그룹의 방을 잘못 할당받지 않는다. 테스트 코드는 암호나 권한 인증 수단이 아니다. **코드가 같다는 사실만으로 소스 호환성을 검사하지는 않으므로 반드시 같은 코드 변경분을 맞춘다.**

## 코드를 수정한 다음

서버 로직이나 네트워크 구조를 바꿨다면 참가자들이 Play를 종료하고 필요한 수정 사항을 공유한다. 컴파일이 끝난 뒤 서버 → 클라이언트 순으로 다시 실행한다. 개발 Play 중 스크립트 컴파일이 시작되면 실행을 종료한다. Photon·Voice 연결은 실행 중 어셈블리 재로드를 유지할 수 없으므로 컴파일·에셋 갱신 중에는 개발 Play 버튼도 비활성화한다. 서버 빌드·배포는 필요 없지만 C# 컴파일, 씬 로딩, Photon 접속 시간은 필요하다. 수정한 코드가 이미 실행 중인 다른 PC에 자동으로 전달되지는 않는다.

방장이 퇴장하면 기존 게임 규칙대로 세션을 종료한 뒤 개발 서버가 Play를 자동으로 다시 시작해 다음 방을 준비한다. 씬·도메인과 DI 객체를 새로 만들므로 이전 방 상태를 재사용하지 않는다. 서버의 **준비됨**을 확인한 뒤 클라이언트의 홈에서 다시 방을 만든다. 서버 담당자가 직접 Play를 끄거나 서버 시작에 실패한 경우에는 자동 재시작하지 않는다. 참가자가 오기 전의 120초 자동 종료는 개발 서버에 적용하지 않는다. 서버 담당자의 PC와 에디터가 실행 중이어야 한다.

서버 담당자도 플레이하려면 **별도 프로젝트 폴더의 두 번째 에디터**를 클라이언트로 실행한다. 같은 프로젝트 폴더를 두 에디터에서 동시에 열지 않는다. 이 작업은 한 에디터 안에서 여러 게임을 동시에 실행하는 Multi-Peer 모드를 추가하지 않는다.

## 기존 작업 환경과의 관계

- 개발 역할과 테스트 코드는 에디터 프로세스의 SessionState에 보관한다. 플레이어 빌드나 Git에 개인 역할을 저장하지 않는다.
- 수동으로 Play를 종료하면 일반 역할로 돌아간다. 방 종료에 따른 서버 자동 재시작은 같은 테스트 코드를 유지한다.
- 개발 모드에서는 기존 `UserSettings/ServerFlowVersion.txt`의 EC2 시험 버전 선택보다 개발용 접속 영역이 우선한다. 파일을 삭제하거나 제품 버전을 바꿀 필요가 없다.
- 버튼으로 시작할 때 Home에서 Play하며, 작업 중인 씬 파일을 열거나 저장하지 않는다. Play 시작 씬과 빠른 Play 옵션은 종료 후 이전 설정으로 복구한다. 개발 서버의 씬 정리가 필요하므로 해당 Play 동안에는 씬·도메인 재로드를 사용한다.
- 서버는 기존 `DedicatedServerStartup`과 실제 서버 권한 판정·씬 흐름을 재사용한다. 에디터 Play의 씬 복사본에도 기존 서버 UI 정리를 적용하고 원본 씬은 수정하지 않는다. Unity의 [OnProcessScene 콜백](https://docs.unity.cn/6000.7/Documentation/ScriptReference/Build.IProcessSceneWithReport.OnProcessScene.html)은 Play 모드 씬 로딩 때에도 호출되며 이 경우 report가 null이다.
- EC2 테스트 호스트·공개 배포·Jenkins 설정은 변경하지 않는다.

## 문제가 생기면

- 메뉴가 안 보이면 스크립트 컴파일 완료와 Console 오류를 먼저 확인한다.
- 방을 못 만들면 서버의 준비 상태, 같은 테스트 코드·제품 버전, 다른 사람이 이미 만든 방이 있는지 확인한다. 이미 방이 있다면 새로 만들지 말고 참가한다.
- 서버 시작이 실패하면 Console의 오류를 확인한다. 같은 코드의 서버가 이미 실행 중이거나 기존 인증 백엔드·Photon 연결에 실패했을 수 있다.
- 서버 종료·재시작 후에는 클라이언트도 홈으로 돌아가 다시 접속한다.

검사: `Game.Architecture.Tests.EditorDevelopmentSessionTests`에서 서버/클라이언트 역할 분리, 실제 Photon 설정의 개발 영역·지역 선택, 잘못된 테스트 코드 거절을 검사한다. 다른 PC의 전체 6인 경기는 별도 수동 검증 범위다.

## 2026-09-14 실행 검증

- 역할·Photon 설정·잘못된 코드에 대한 EditMode 검사 3개 통과.
- 격리 에디터 서버를 실제 Photon에 연결하고 세션 종료 후 같은 코드로 자동 재준비됨을 확인했다.
- 실행 중 실제 스크립트 재컴파일을 요청해 Play 종료, 역할·시작 씬·Play 옵션 복구, 재실행을 확인했다. Play 정리 전에 어셈블리가 바뀌면 Voice 내부 연결이 소실되므로 정리가 끝날 때까지 재로드를 보류한다.
- 원본 에디터 클라이언트에서 **방 만들기 → 입장·이동 → 퇴장 → 다시 방 만들기 → 입장·이동**이 오류 없이 성공했음을 사용자가 확인했다. 서버 로그에서도 방 종료·재준비·재접속을 확인했다.
- 이는 로컬 서버 에디터와 별도 클라이언트 에디터의 반복 접속 검증이다. 서로 다른 PC의 6인 경기, 음성 송수신 품질, 전체 게임의 회귀 검증 완료를 의미하지 않는다.
