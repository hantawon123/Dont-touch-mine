# 서로 다른 PC의 WebGL 6인 확인

이 확인은 사용자가 직접 진행한다. 같은 PC에서 실행한 여러 클라이언트의 결과로 대신하지 않는다. MR 생성과 운영 배포는 별도로 결정한다.

## 준비

1. 검증 보고서에 기록된 **동일 버전**의 서버 실행 파일과 WebGL 빌드를 사용한다. 예전 공개 빌드와 섞으면 서로 다른 Photon 버킷에 들어간다.
2. 서버용 PC 한 대에서 서버 프로세스 하나를 실행한다. 플레이어 6명과 별개 프로세스이며, 플레이어 PC 중 하나에서 함께 실행해도 된다. 서버를 구매할 필요는 없다.
3. 각 플레이어는 서로 다른 PC·브라우저 프로필을 사용하고 같은 Photon 지역을 선택한다. 계정 토큰이나 기기 ID를 서로 전달하지 않는다.
4. 각 PC에 WebGL 빌드 폴더와 `serve.py`를 복사하고 `python serve.py <WebGL 폴더>`를 실행해 `http://localhost:4291`을 연다. 최초 닉네임 설정 등 정상 로그인 절차를 마친다. `file://`로 HTML을 직접 열지 않는다. 운영 사이트 재개나 Jenkins 활성화는 이 절차에 포함하지 않는다.
5. 서버 로그에서 `[Server] Ready`를 확인하고 120초 안에 첫 참가자가 방을 만든다. 빈 서버는 자동 종료되므로 시간이 지나면 다시 실행한다.

```text
ServerFlow988.exe -batchmode -nographics -gameServer -roomCode 988ABC -region kr -logFile <server.log>
```

검증 드라이버용 `-validationPeer`는 수동 검증에서 사용하지 않는다. 서버 창이 없어도 프로세스와 로그가 유지되어야 한다.

## 경기 1회차

1. A가 방을 생성한다. B~F는 방 목록 또는 코드로 입장한다. 화면의 인원수는 서버를 제외한 **6명**이어야 한다.
2. A만 설정 변경·시작·강퇴 메뉴를 사용할 수 있어야 한다. A는 방장이지만 경기 서버로 실행되는 플레이어가 아니다.
3. 경기를 시작하고 6명 모두 같은 경기 씬으로 들어가는지 확인한다. 각자의 비공개 아이템 배정과 차례 안내를 확인한다.
4. 각 플레이어가 실제로 이동·점프·물건 집기·던지기를 수행한다. 다른 화면에서 위치와 물건 결과가 수렴하는지 확인한다. 벽·바닥 충돌, 파쇄기 판정도 확인한다.
5. 탐색 중 F가 정상 퇴장한다. A~E가 멈추거나 로비로 튕기지 않고 경기를 계속해야 한다. 서버가 F의 이탈을 기록해야 한다.
6. 남은 인원의 결과와 하이라이트가 표시되는지 확인한다. 종료·점수·승패가 서로 모순되지 않아야 한다. 음성은 실제 참가자 브라우저의 마이크 권한을 허용한 경우 별도로 확인한다.

## 재경기와 종료

1. 결과에서 로비로 돌아가 남은 5명이 같은 방에 있는지 확인한다.
2. A가 다시 시작한다. 지난 경기의 아이템·타이머·탈락 상태가 재사용되지 않고 새 경기가 진행되어야 한다.
3. 재경기 도중 A가 퇴장한다. B~E에게 방 종료가 안내되고 모든 클라이언트가 빠져나와야 한다. 다른 참가자가 게임 서버로 승격되면 실패다.
4. 서버 로그의 `[Server] Session closed`와 프로세스 종료를 확인한다. 새 서버를 실행해 새 방을 만들 수 있어야 한다.

## 추가 실패 경로

- 서버 프로세스가 없을 때 방 만들기: 실패 안내가 나오며 플레이어 Host 방이 만들어지지 않아야 한다.
- 비밀번호 방: 틀린 비밀번호는 거절되고 올바른 비밀번호만 입장 가능해야 한다.
- 비공개 방: 목록에는 없고 코드를 아는 참가자만 해당 방을 찾아야 한다. 비밀번호를 설정했다면 코드만으로 통과할 수 없어야 한다.
- 정원이 찬 방과 시작 카운트다운 이후의 추가 입장이 거절되어야 한다.
- 일반 참가자의 강제 종료와 서버 프로세스의 비정상 종료도 각각 확인한다. 서버 중단 시 클라이언트가 무한 로딩에 남아서는 안 된다.

## 결과 기록

빌드 버전, 시간, Photon 지역, 각 PC의 OS/브라우저, 확인 항목별 성공/실패를 적는다. 실패 시 어느 화면에서 어떤 동작 뒤 발생했는지와 서버 로그의 해당 시각을 남긴다. 토큰·기기 ID·전체 인증 응답은 첨부하지 않는다. 성능 수치는 PC와 브라우저별로 측정하며, 로컬 흐름 검증 통과를 120 FPS 보장으로 해석하지 않는다.
