# 플레이 로그 히트맵

관리 화면 분석 탭의 「맵 위 히트맵」 카드 설명입니다. 표(3·4번 절)는 "숫자가 큰 칸"만 보여 주지만
이 카드는 구운 평면도 위에 그 칸이 **어디인지** 보여 줍니다. 브라우저의 canvas 가 그리고, 값은 좌표 API
(`GET /api/v1/admin/analytics/positions`)와 3·4번 절의 질의에서 옵니다.

**쿼리는 여기에 없습니다.** SQL 은 [`analytics-dashboards.md`](analytics-dashboards.md) 가 원본이고
카드는 그 결과만 그립니다. 표와 그림이 다른 값을 보면 안 되기 때문입니다.

**한 번에 한 맵, 한 층입니다.** 맵은 화면 위쪽에서 고르고, 층이 겹치는 맵은 구운 평면도가 담은 층만
그립니다. 아래 「맵을 먼저 고릅니다」 와 「층이 겹치는 맵은 한 층만 그립니다」 를 보세요.

2026-09-16 까지는 Metabase 에서 내려받은 CSV 를 PNG 로 바꾸는 파이썬 도구(`Tools/analytics/heatmap.py`)가
이 자리에 있었습니다. 카드가 맵 위 겹치기까지 하게 되어 도구와 Metabase 를 함께 내렸습니다
(S15P21D205-979). 필요하면 git 히스토리에 있습니다.

## 평면도 굽기 (S15P21D205-1010)

바닥에 깔 평면도는 유니티에서 굽습니다.

```
Game/Match Map/Bake Analytics Floorplan...
```

맵의 환경 루트를 고르고 범위를 잰 뒤, 잘라 낼 높이를 지붕보다 낮게 잡고 굽습니다. 그냥 위에서
찍으면 지붕만 나오기 때문입니다. **층이 겹치는 맵은 「한 층만 담은 그림」을 켜고 그 층의 y 범위를
적습니다** - 그 값이 JSON 에 따라가서 화면이 다른 층을 거릅니다. 결과는 두 파일입니다.

```
backend/app/src/main/resources/static/admin/maps/<mapId>.png
backend/app/src/main/resources/static/admin/maps/<mapId>.json
```

**JSON 을 지우지 마세요.** 그 안에 그림이 덮는 월드 사각형이 있고, 관리 화면은 그 값을 그림과
격자 양쪽에 씁니다. 두 곳에 같은 숫자를 손으로 적으면 언젠가 어긋나는데, 어긋나면 사람이 벽
안에 서 있는 것처럼 보입니다. 그건 틀렸다는 티가 안 나서 더 나쁩니다.

JSON 이 없으면 화면이 내장 표의 범위로 경계만 그립니다. 맵을 옮기거나 넓히면 다시 구우면
됩니다.

### 저택 1층 굽는 값 (S15P21D205-1085)

아직 굽지 않았습니다. `Mansion` 씬을 열고 위 메뉴에서 이렇게 넣으면 됩니다. 값은
[`docs/design/match-map/mansion/README.md`](../../docs/design/match-map/mansion/README.md) 6절의 경계
콜라이더 실측입니다.

| 칸 | 값 |
| --- | --- |
| 환경 루트 | `MansionEnvironment` |
| 맵 id | `mansion` |
| 가로 x | -13 ~ 13.5 |
| 세로 z | -33 ~ -8.5 |
| 잘라 낼 높이 y | 5 (2층 바닥 5.5 아래) |
| 한 층만 담은 그림 | 켬, `1층`, y 0.7 ~ 5 |

굽기 전에도 히트맵은 이 범위로 경계를 그리고 1층만 남깁니다. 화면에 같은 값이 내장 표
(`static/admin/index.html` 의 `MAPS`)로도 있기 때문인데, **구운 JSON 이 있으면 그쪽이 기준입니다.**

#### 배경만 찍히면 (2026-09-19)

첫 굽기가 배경색 한 가지와 마젠타 180 픽셀뿐인 PNG 를 냈습니다. PC 품질 설정이 2026-09-16 에
**GPU 상주 드로어**를 켰는데(S15P21D205-994), 정적 소품을 GPU 가 직접 그리는 그 경로가 손으로 만들어
`Camera.Render()` 로 한 장 찍는 카메라에는 따라오지 않습니다. 그 그림에서 유일하게 찍힌 것이 그 경로를
타지 않는 오류 셰이더 물건 하나였습니다. 마트를 구운 2026-09-15 에는 꺼져 있어서 멀쩡히 나왔습니다.

지금은 도구가 굽는 동안만 그것을 끄고 셰이더도 동기로 컴파일합니다. 그리고 **배경만 찍히면 파일을
쓰지 않습니다** - 칠해진 픽셀 비율과 범위 안 렌더러 수를 알려 줍니다. 렌더러가 0 이면 범위가 틀린
것이고, 0 이 아닌데 비었으면 그리는 쪽이 틀린 것입니다. 회색 바닥은 둘을 구분해 주지 않아서 값을
따로 적습니다.

### 맵을 먼저 고릅니다 (S15P21D205-1085)

**화면 위쪽, 기간 옆에 맵 고르는 칸이 있습니다.** 여기서 고른 맵이 분석 탭 전체에 걸립니다 - 히트맵만이
아니라 표와 막대까지 그 맵의 경기만 셉니다. 조회 API 가 `mapId` 를 받아 각 절의 `/* @filter */` 자리에
`AND map_id = ?` 를 넣습니다.

마트와 저택은 크기도 동선도 달라서 둘을 합친 평균은 어느 맵의 값도 아닙니다. 그리고 히트맵은 평면도 한
장 위에 그리는 그림이라 애초에 두 맵을 겹칠 수 없습니다.

`전체 맵` 으로 두면 히트맵은 **행이 가장 많은 맵 하나**를 그리고 그 사실을 카드에 적습니다. 2026-09-19
전까지는 첫 행의 맵을 말없이 골라서, 나머지 맵의 값이 어디로 갔는지 화면에 아무 말이 없었습니다.

맵을 바꾸면 **골라 둔 경기는 풀립니다.** 경기는 한 맵의 것이라, 안 풀면 모든 카드가 빈 표가 됩니다.

### 무엇을 그릴지 고릅니다

카드 위 첫 칸에서 고릅니다.

| 항목 | 무엇 | 범위 | 질의 |
| --- | --- | --- | --- |
| 사람 체류 · 경기 하나 | 고른 경기의 위치 샘플 | 경기 하나 | 좌표 API |
| 사람 체류 · 기간 전체 | 사람이 머문 칸의 샘플 수 | 기간 전체, 경기를 고르면 그 경기 | 문서 4번 절 |
| 은신처 · 숨긴 횟수 | 그 칸에 물건을 숨긴 횟수 | 같음 | 문서 3번 절 |
| 은신처 · 버틴 시간 | 버틴 시간 평균(초) | 같음 | 문서 3번 절 |
| 은신처 · 끝까지 안 들킨 비율 | 안 들킨 비율(%) | 같음 | 문서 3번 절 |

아래 넷은 「은신처 분포」·「체류 구역」 카드의 질의를 그대로 씁니다. 표와 그림이 다른 숫자를 보이면 안
되기 때문입니다. 이미 2 m 칸으로 묶여 오므로 칸 크기를 고를 수 없고 플레이어도 못 나눕니다. 단계는 4번
절이 컬럼으로 주므로 「사람 체류 · 기간 전체」에서만 고를 수 있습니다.

**경기 하나와 기간 전체가 딱 맞아떨어지지 않을 수 있습니다.** 4번 절은 `dropped_samples = 0` 도 걸어서
샘플 상한에 걸린 경기를 통째로 뺍니다. 구역 비교를 왜곡하기 때문인데, 그 경기를 직접 고르면 좌표 API 는
그대로 보여 줍니다.

### 층이 겹치는 맵은 한 층만 그립니다

저택은 본관 1층 위에 2층이 있고 그 위 다락이 **대기 구역**입니다. 셋이 x·z 로 겹칩니다.

평면도는 한 층을 찍은 그림이므로, 다른 층의 좌표를 그 위에 얹으면 벽 안에 사람이 서 있는 그림이 나옵니다.
더 나쁜 것은 다락입니다 - 자기 차례가 아닌 사람이 몇 분씩 서 있어서, 그 칸이 제일 뜨거워지고 본관 안의
차이가 색으로 안 보입니다. 마트의 대기실은 x 로 떨어져 있어 범위에서 뺐지만, 저택 다락은 본관 바로 위라
그 수가 안 통합니다.

그래서 맵 JSON 의 `floor` 가 이 그림이 담은 y 범위를 들고 있고, 화면은 그 밖의 값을 버립니다. 몇 줄을
버렸는지는 카드 아래 범례에 적힙니다.

| | 값 |
| --- | --- |
| 저택 1층 | y 0.7 ~ 5.0 (1층 바닥 1.01, 2층 바닥 5.5) |
| 마트 | 층 없음. 한 층이라 거르지 않습니다 |

문서 3·4번 절은 `y(5m)` 컬럼으로 층을 나눠 줍니다(`FLOOR(y / 5) * 5`). 저택은 1층이 밴드 0, 2층과 다락이
밴드 5 이고 마트는 전부 밴드 0 입니다. 한 칸이 두 밴드로 쪼개져 오면 화면이 다시 합칩니다 - 횟수는 더하고,
버틴 시간은 숨긴 횟수로 가중평균, 안 들킨 비율은 합친 횟수로 다시 셉니다. 자세한 것은
[`analytics-dashboards.md`](analytics-dashboards.md) 의 「공통: 맵과 층」 입니다.

**발견까지 평균(초)은 히트맵에 없습니다.** 들킨 물건만 세는 값이라 좋은 자리일수록 짧아 보입니다.
색으로 칠하면 결론이 뒤집히므로 표에만 둡니다. 자세한 이유는
[`analytics-dashboards.md`](analytics-dashboards.md) 의 3번 절에 있습니다.

숨긴 횟수가 3회 미만인 칸은 흐리게 그립니다. 한 번 숨겨 안 들켰다고 안전한 자리가 아닙니다.

### 사람마다 보기

`전체 플레이어` 칸에서 한 명을 고르면 그 사람 것만 그립니다. 「사람 체류 · 경기 하나」에서만 됩니다 -
나머지는 이미 묶여 와서 그 안을 못 나눕니다.

### 색 읽는 법

색 띠와 그 아래 숫자가 카드 밑에 있습니다. 진한 칸이 몇 개인지 거기서 읽습니다. 칸 위에 마우스를
올리면 그 칸의 좌표와 개수가 조작부 오른쪽에 나옵니다.

**로그 눈금**은 색을 개수에 비례해 칠할지, 로그를 씌워 칠할지입니다. 한 칸이 유독 높으면 나머지가
전부 옅은 색으로 뭉개지는데, 그때 켜면 작은 차이가 보입니다. 대신 색으로 양을 비교할 수 없게
됩니다. 두 배 진하다고 두 배 많은 것이 아닙니다. 켜고 끄면 색 띠 아래 숫자가 같이 바뀝니다.

**평면도는 회색조로 깝니다.** 매대의 주황 과일과 노란 상자가 열과 같은 색이라, 바탕이 총천연색이면
어디까지가 열이고 어디부터가 상품인지 구분되지 않습니다. 지형을 확인해야 할 때만 원래 색 체크박스를
켜세요.

### 대기실은 범위에서 뺍니다

마트와 같은 씬의 서쪽(x -48 ~ -40)에 대기실이 따로 있습니다. 숨기기 단계에는 자기 차례가 아닌
사람이 거기 서 있어서 그 좌표가 기록에 남습니다.

범위에 넣으면 사람들이 몇 분씩 가만히 서 있는 그 방이 제일 뜨거워지고, 마트 안의 차이가 색으로
안 보입니다. 그래서 굽는 범위와 격자 범위 모두 마트 실내만 잡습니다. 대기실 좌표는 경계 밖으로
버려지고, 몇 개를 버렸는지는 카드 아래 범례에 숫자로 적힙니다.

찾기 단계만 보면 전원이 마트 안에 있으므로 이 문제가 없습니다. 카드의 단계 고르는 칸을 쓰면
됩니다.

경계 콜라이더를 통째로 합치면 안 됩니다. 바닥·천장 판이 실내보다 커서 세로가 75 m 로 나옵니다.
바깥 벽 넷만 봅니다.

| 벽 | 안쪽 면 |
| --- | --- |
| 서 | x -25.51 |
| 동 | x 21.49 |
| 남 | z -41.20 |

스폰 지점 10개, 파쇄기 2개, 마트 쪽 CCTV 가 모두 이 안에 들어옵니다. 대기실 스폰 10개는 밖입니다.

### 좌표계가 한 번 바뀐 적이 있습니다

2026-09-10 에 씬 루트를 (+108.49, -0.98) 옮겨 원점을 마트 안에 두었습니다
(`docs/design/match-map/README.md`). 화면에 박아 둔 범위가 그때 따라가지 않아서, 모든 좌표가
범위 밖으로 걸러져 히트맵이 빈 격자로 보였습니다. 2026-09-15 에 고쳤습니다.

빈 격자는 "아무도 그 칸에 안 갔다"와 구분되지 않습니다. 범위를 손으로 적는 한 이 일은 또
일어나므로, 구운 평면도가 있으면 그 JSON 이 기준입니다.
