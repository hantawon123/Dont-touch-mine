# 플레이 로그 히트맵

`Tools/analytics/heatmap.py` 사용법입니다. Metabase 3·4번 화면이 내주는 격자 CSV 를 공간
히트맵 PNG 로 바꿉니다. 표에서는 "숫자가 큰 칸"만 보이지만 그림에서는 **어디인지**가 보입니다.

**쿼리는 여기에 없습니다.** SQL 은 [`analytics-dashboards.md`](analytics-dashboards.md) 가 원본이고
이 도구는 그 결과만 그립니다. 둘이 다른 값을 보면 안 되기 때문에 도구는 SQL 을 갖지 않습니다.

**내 PC 에서 돌립니다.** CSV 를 받는 것도 PNG 를 보는 것도 사람이 하는 일이라 서버에 올릴
이유가 없습니다. EC2 에는 15GB 에 Jenkins·MySQL·Metabase·앱이 이미 같이 있습니다.

## 처음 한 번

`matplotlib` 만 있으면 됩니다. `numpy` 는 대부분 이미 있습니다.

```
pip install matplotlib
```

**conda 를 쓴다면 프롬프트의 환경을 보세요.** 프롬프트가 `(base)` 로 시작하면 그 환경에
설치됩니다. 나중에 다른 창에서 `python` 을 부르면 conda 가 아닌 파이썬이 잡혀
`ModuleNotFoundError: matplotlib` 이 납니다. 설치할 때와 실행할 때 같은 프롬프트를 쓰세요.
어느 파이썬이 잡히는지는 이걸로 봅니다.

```
python -c "import sys; print(sys.executable)"
```

## 쓰는 순서

**1. Metabase 에서 CSV 내려받기.** 대시보드에서 3번 「은신처 분포」 또는 4번 「체류 구역」
화면을 열고, 표 오른쪽 아래 내려받기에서 `.csv` 를 고릅니다.

헤더를 손볼 필요가 없습니다. `x(2m)`·`z(2m)`·`체류 샘플` 같은 한글 이름을 그대로 알아봅니다.
**고치지 마세요** - 고치는 순간 화면과 그림이 다른 값을 보게 됩니다.

**2. 저장소 최상위에서 실행.**

```
python Tools/analytics/heatmap.py 체류구역.csv -o dwell.png
```

**3. 출력 줄 읽기.** 저장 경로와 값 범위를 찍습니다. 색이 뭉개질 상황이면 그것도 알려 줍니다.

```
dwell.png 에 저장했습니다. 패널 2개, 값 1 ~ 948
  한 칸이 중앙값의 56배입니다. --log 를 붙이면 나머지가 보입니다.
```

두 번째 줄이 나오면 `--log` 를 붙여 다시 돌리세요.

## 자주 쓰는 조합

**숨는 단계와 찾는 단계를 나눠 보기.** 사람이 어디에 머무는지는 단계마다 완전히 다릅니다.
섞어 보면 둘 다 안 보입니다.

```
python Tools/analytics/heatmap.py 체류구역.csv --split-by 단계 --log -o dwell.png
```

**물건 자리와 사람 자리를 나란히 보기.** "물건은 있는데 아무도 안 가는 구역"과 "사람만
지나가는 구역"이 여기서 갈립니다. CSV 를 둘 주면 좌표 범위를 맞춰 나란히 그립니다.

```
python Tools/analytics/heatmap.py 은신처.csv 체류구역.csv -o compare.png
```

**칸이 너무 잘아서 얼룩덜룩할 때.** 맵이 넓거나 경기 수가 적으면 2m 칸이 너무 잘게 나뉩니다.
**CSV 가 이미 2m 로 묶여 있으므로 4·6 처럼 2의 배수를 쓰세요.** 3 이나 5 를 주면 칸이 어긋납니다.

```
python Tools/analytics/heatmap.py 체류구역.csv --cell 4 -o dwell.png
```

**발표 자료에 넣을 큰 그림.** 기본 140dpi 는 화면용입니다. 슬라이드에 크게 넣으면 흐려집니다.

```
python Tools/analytics/heatmap.py 체류구역.csv --split-by 단계 --dpi 220 --title "1차 플레이테스트 체류 구역" -o dwell.png
```

## 그림 읽는 법

색은 `값 없음(회색) → 낮음(옅은 노랑) → 높음(진한 빨강)` 입니다.

**회색은 기록이 아예 없는 칸입니다.** 값이 0 인 것과 다릅니다. 흰색으로 두면 "없음"이
"낮음"보다 밝아 보여 눈이 순서를 거꾸로 읽기 때문에 회색으로 칠합니다.

- **가로가 x, 세로가 z 입니다.** 유니티 월드 좌표 그대로이고 위쪽이 +z 입니다. 맵을 위에서
  내려다본 그림과 방향이 같습니다. (코드에서 `origin="lower"` 입니다. 기본값으로 두면 위아래가
  뒤집히는데, 벽이 없는 그림에서는 뒤집혀도 그럴듯해 보여 알아채기 어렵습니다.)
- **가로세로 비율은 1:1 고정입니다.** 찌그러뜨리면 좁은 복도가 넓어 보여 거리 감각이 무너집니다.
- **패널끼리 좌표 범위를 함께 씁니다.** 화면상 같은 자리는 어느 패널에서든 같은 월드 좌표입니다.
  패널마다 자기 데이터로 범위를 잡으면 나란히 놓는 의미가 사라집니다.
- **색 눈금은 같은 지표끼리만 공유합니다.** `숨긴 횟수`(최대 수십)와 `체류 샘플`(최대 수백)을
  한 눈금에 놓으면 작은 쪽이 통째로 뭉갭니다. 단계별 패널처럼 같은 지표는 눈금을 공유해
  서로 비교됩니다.
- **샘플 수는 대략 초입니다.** 정확한 초가 아닙니다 - 프레임이 밀리면 샘플이 빠집니다. 절대
  시간이 아니라 구역 사이의 비교로만 읽으세요.

## 옵션

| 옵션 | 기본값 | 하는 일 |
| --- | --- | --- |
| `-o`, `--out` | `heatmap.png` | 저장할 PNG 경로 |
| `--split-by` | | 이 열의 값마다 패널을 나눕니다. 보통 `단계` |
| `--log` | 꺼짐 | 색을 로그 눈금으로. 한두 칸이 압도적으로 클 때 |
| `--cell` | `2.0` | 격자 한 칸의 크기(m). CSV 가 2m 로 묶였으므로 2의 배수 |
| `--title` | | 그림 전체 제목 |
| `--dpi` | `140` | 해상도. 인쇄·슬라이드용은 200 이상 |
| `--cmap` | `YlOrRd` | 컬러맵. 흰 배경용 기본값. 어두운 맵 위에는 `inferno` |
| `--independent-scale` | 꺼짐 | 패널마다 색 눈금을 따로. 비교를 포기하고 패널 내부 대비를 살릴 때 |
| `--x` `--z` `--w` | 자동 인식 | 열 이름을 직접 지정. 헤더를 못 알아볼 때만 |
| `--map` | | 배경에 깔 맵 이미지. `--extent` 와 함께 |
| `--extent` | | `X0 Z0 X1 Z1`. 맵 이미지가 덮는 월드 좌표 범위 |

## 막혔을 때

**`matplotlib 이 없습니다.`** 설치가 안 됐거나, 설치한 환경과 실행하는 환경이 다릅니다.
위 "처음 한 번"의 `sys.executable` 로 어느 파이썬이 잡히는지 먼저 보세요.

**`x 열을 찾지 못했습니다. 있는 열: …`** 3·4번이 아닌 화면의 CSV 이거나 열 이름을 고친
경우입니다. 메시지가 실제 열 목록을 같이 보여 주므로 거기서 골라 `--x` `--z` `--w` 로
지정하면 됩니다.

**한글이 □□□ 로 나옵니다.** 한글 폰트를 못 찾은 것입니다. 윈도우에는 맑은 고딕이 있어 보통
생기지 않습니다. 그때는 `한글 폰트를 찾지 못했습니다` 경고가 같이 찍히므로, 그 줄이 없으면
다른 문제입니다.

**거의 다 옅은 노랑이고 한 칸만 진합니다.** 한 칸이 나머지를 압도하고 있습니다. `--log` 를
붙이세요. 도구가 먼저 알려주기도 합니다.

**그림이 온통 회색입니다.** 기록이 없는 칸이 대부분이라는 뜻이고, 대개 경기 수가 너무 적은
것입니다. Metabase 1번 화면에서 `완전 수신` 이 1 인 경기가 몇 판인지 먼저 보세요.

## 아직 안 되는 것

**맵 그림 위에 겹치기.** `--map` 과 `--extent` 로 받을 준비는 되어 있지만, 맵을 위에서 찍은
이미지와 그 이미지가 덮는 월드 좌표 범위가 있어야 합니다. 지금은 둘 다 없습니다. 맵이
정해지면 한 번 만들어 두면 그 뒤로는 계속 씁니다.

그때는 `--cmap inferno` 가 낫습니다. 기본값은 흰 배경에서 낮은 값이 옅게 보이도록 고른
것이고, 어두운 맵 위에서는 옅은 색이 묻힙니다.

## 어디까지 확인했나

**합성 데이터까지입니다** (2026-09-10). 아는 칸에만 값을 넣어 축이 뒤바뀌지 않는지, 위아래가
뒤집히지 않는지 확인했고, 군집이 있는 가짜 데이터로 그림 모양을 봤습니다. 만드는 과정에서
세 가지를 고쳤습니다 - 패널마다 좌표 범위가 달라 비교가 안 되던 것, 다른 지표끼리 색 눈금을
공유해 작은 쪽이 새까맣게 뭉개지던 것, 빈 칸이 낮은 값보다 밝아 순서가 거꾸로 읽히던 것.

**실제 플레이 데이터로는 아직 확인하지 않았습니다.** 축·색·배치는 맞지만 실제 맵 크기에서
2m 격자가 적당한지는 그때 봐야 압니다. 너무 잘게 나오면 `--cell 4` 로 키우세요.

## 관리 화면 히트맵의 평면도 (S15P21D205-1010)

관리 화면 분석 탭 9번 카드는 이 문서의 파이썬 도구와 별개로 브라우저에서 그립니다. 바닥에 깔
평면도는 유니티에서 굽습니다.

```
Game/Match Map/Bake Analytics Floorplan...
```

맵의 환경 루트를 고르고 범위를 잰 뒤, 잘라 낼 높이를 지붕보다 낮게 잡고 굽습니다. 그냥 위에서
찍으면 지붕만 나오기 때문입니다. 결과는 두 파일입니다.

```
backend/app/src/main/resources/static/admin/maps/<mapId>.png
backend/app/src/main/resources/static/admin/maps/<mapId>.json
```

**JSON 을 지우지 마세요.** 그 안에 그림이 덮는 월드 사각형이 있고, 관리 화면은 그 값을 그림과
격자 양쪽에 씁니다. 두 곳에 같은 숫자를 손으로 적으면 언젠가 어긋나는데, 어긋나면 사람이 벽
안에 서 있는 것처럼 보입니다. 그건 틀렸다는 티가 안 나서 더 나쁩니다.

JSON 이 없으면 화면이 내장 표의 범위로 경계만 그립니다. 맵을 옮기거나 넓히면 다시 구우면
됩니다.
